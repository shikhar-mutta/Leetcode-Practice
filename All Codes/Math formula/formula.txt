[4] 2D Cross Product — Collinearity Check (LeetCode 1037)
    Given 3 points: p1(x1,y1), p2(x2,y2), p3(x3,y3)
    Build vectors from p1:
        v1 = p2 - p1 = (x2-x1, y2-y1)
        v2 = p3 - p1 = (x3-x1, y3-y1)

    Cross product: v1 × v2 = (x2-x1)*(y3-y1) - (x3-x1)*(y2-y1)

    = 0   → collinear (same line)
    ≠ 0   → form a triangle

    Code: return (x2-x1)*(y3-y1) != (x3-x1)*(y2-y1);

[5] Slope Comparison — Collinearity Check (LeetCode 1232)
    Fix first two points to get reference slope: dx = x1-x0, dy = y1-y0
    For every subsequent point (x, y), check:

        dx * (y - y0) == dy * (x - x0)

    Avoids division; equivalent to dy/dx == (y-y0)/(x-x0) cross-multiplied.
    All points collinear ↔ all pass this check.

    Code: if (dx*(y-y0) != dy*(x-x0)) return false;

[6] XOR Subset Sum (LC 1863)
    Formula: Sum of XOR totals of ALL subsets = OR(all elements) * 2^(n-1)

    Brief: For any bit b, split array into Group A (no bit b) and Group B (has bit b).
           Group A → free to include/exclude → 2^k ways.
           Group B → need odd count → half qualify → 2^(m-1) ways.
           Total = 2^k * 2^(m-1) = 2^(n-1)  [since k+m=n, always cancels].
           Every bit that appears contributes bit_value * 2^(n-1) → sum = OR * 2^(n-1).

    Proof (bit-by-bit argument):
      Fix any bit position b. Ask: how many subsets have bit b SET in their XOR?
      A subset's XOR has bit b set  iff  an ODD number of its elements have bit b.

      Split the array into two groups for bit b:
        Group A (size k) — elements that do NOT have bit b  →  don't affect bit b at all
        Group B (size m) — elements that DO    have bit b  →  need odd count among these

      Counting valid subsets:
        Group A: freely include or exclude any element  →  2^k choices
        Group B: need odd count  →  exactly half of 2^m subsets qualify  →  2^(m-1)
        Total = 2^k * 2^(m-1) = 2^(k+m-1) = 2^(n-1)   [since k+m = n]

      This holds for EVERY bit b that appears in at least one element.
      Summing contributions of all bits:
        answer = sum over each bit b of [2^b * 2^(n-1)]
               = OR(all elements) * 2^(n-1)

    Example: nums = [1, 2, 3]   →   1=01,  2=10,  3=11  (binary)
      Bit 0 (value=1):
        Group A (no bit 0) = {2},      k=1
        Group B (has bit 0) = {1, 3},  m=2
        Subsets with bit 0 in XOR = 2^1 * 2^1 = 2^(3-1) = 4
        Contribution to answer = 1 * 4 = 4

      Bit 1 (value=2):
        Group A (no bit 1) = {1},      k=1
        Group B (has bit 1) = {2, 3},  m=2
        Subsets with bit 1 in XOR = 2^1 * 2^1 = 2^(3-1) = 4
        Contribution to answer = 2 * 4 = 8

      answer = 4 + 8 = 12
      OR(1,2,3) * 2^(3-1) = 3 * 4 = 12 ✓
      Brute: {1}=1, {2}=2, {3}=3, {1,2}=3, {1,3}=2, {2,3}=1, {1,2,3}=0  →  sum=12 ✓

    Code: return orAll * (1 << (n - 1));

[7] Find Repeated & Missing using Sum + Sum of Squares (LC 2965)
    Let a = repeated number, b = missing number, N = total elements (n*n).

    Step 1 — Build two equations:
        diff   = sum(grid)   - N*(N+1)/2          →  a - b
        sqDiff = sqSum(grid) - N*(N+1)*(2N+1)/6   →  a² - b²

    Step 2 — Use difference of squares: a² - b² = (a+b)(a-b)
        sqDiff / diff  =  a + b

    Step 3 — Solve the 2-equation system:
        a - b = diff
        a + b = sqDiff / diff

        a (repeated) = (sqDiff/diff + diff) / 2
        b (missing)  = a - diff

    ⚠ Use long long for all intermediates — N*(N+1)*(2N+1) overflows int.

    Code:
        long long t = (long long)n * n;
        long long actualSum   = t * (t + 1) / 2;
        long long actualSqSum = t * (t + 1) * (2*t + 1) / 6;
        long long diff   = sum   - actualSum;
        long long sqDiff = sqSum - actualSqSum;
        int repeated = (int)((sqDiff / diff + diff) / 2);
        int missing  = (int)(repeated - diff);

[8] Sum of k elements starting from maxNum (each step +1):
    maxNum + (maxNum+1) + ... + (maxNum+k-1)
    = k * maxNum + (0 + 1 + ... + (k-1))
    = k * maxNum + k*(k-1)/2

    - k * maxNum  : maxNum repeated k times
    - k*(k-1)/2   : sum of first (k-1) natural numbers (0 to k-1)
    - Use case: pick max, add 1, repeat k times → maximize sum (LC 2656)

[9] Minimum x such that x | (x+1) = p  (LC 3314)
    p = 2 → no solution, return -1.

    Idea: x+1 flips x's lowest 0-bit and clears all bits below it.
          So x | (x+1) fills all bits up to that 0-bit with 1s.

    For odd prime p = ...?0 111  (j trailing 1s, first 0 at position j):
      → x = p - 2^(j-1)   i.e. clear the highest trailing 1-bit of p

    Code: count trailing 1s → k doubles each step → answer = p - k/2

    p=7  (111):  j=3, k=8  → x = 7-4  = 3   | 3|4  = 111 = 7  ✓
    p=5  (101):  j=1, k=2  → x = 5-1  = 4   | 4|5  = 101 = 5  ✓
    p=11 (1011): j=2, k=4  → x = 11-2 = 9   | 9|10 = 1011 = 11 ✓

[10] LCM, GCD, Product — Equal Products Condition (LC 3411)

    Classical identity (2 numbers):
        lcm(a, b) * gcd(a, b) = a * b   (always true)

    Incremental LCM update (avoids overflow — divide before multiply):
        lcm = lcm / gcd(lcm, x) * x

    Incremental GCD update:
        g = gcd(g, x)
        Init with g = 0, since gcd(0, x) = x  →  first step gives g = nums[0]

    Equal Products Condition:
        product(subarray) == lcm(subarray) * gcd(subarray)

    Key property (for early break):
        Once product > lcm * gcd, it stays that way forever.
        Proof: adding element x gives new_lcm * new_gcd ≤ lcm*x*gcd < prod*x = new_prod
        So equality can never be restored → safe to break early.

    Observation:
        k=1 → product < lcm*gcd  (product=a, lcm*gcd=a²)
        k=2 → product = lcm*gcd  (always, by the classical identity)
        k≥3 → product ≥ lcm*gcd  (equality is the condition we want)

[11] Prime Check — 6k±1 Optimization (LC 3591)

    Every prime > 3 is of the form 6k±1.
    Reason: out of 6k, 6k+1, ..., 6k+5 — only 6k+1 and 6k+5 (=6k-1) are not
    divisible by 2 or 3. So only check those.

    Code:
        bool isPrime(int n) {
            if (n < 2) return false;
            if (n < 4) return true;          // 2, 3
            if (n%2==0 || n%3==0) return false;
            for (int i = 5; i*i <= n; i += 6)
                if (n%i==0 || n%(i+2)==0) return false;
            return true;
        }

    i covers 6k-1 (e.g. 5,11,17,...), i+2 covers 6k+1 (e.g. 7,13,19,...)
    Example: n=25 → i=5, 25%5==0 → not prime ✓
             n=49 → i=5: no; i=7, 49%7==0 → not prime ✓
             n=13 → i=5: 13%5≠0, 13%7≠0; i=11 > √13 → prime ✓

    Speed: checks only ~n/3 divisors vs ~n/2 for odd-only → 33% faster.

[12] Rightmost Set Bit Isolation

    int bit = x & ~(x - 1);   // or equivalently: x & (-x)

    x-1 flips the lowest set bit and sets all bits below it.
    ~(x-1) then has 1s at the lowest set bit and above.
    ANDing with x isolates only the lowest set bit.

    Example: x = 12 (1100) → x-1 = 11 (1011) → ~(x-1) = ...0100 → x & ~(x-1) = 0100

    Common use: split an array into two groups by a differing bit (e.g. Single Number III).

[13] Integer Ceiling Division (no float / no ceil())

    ceil(a / b)  =  (a + b - 1) / b      // pure integer arithmetic

    Why it works:
      - If a % b == 0: adding (b-1) doesn't reach the next multiple → same as a/b
      - If a % b != 0: adding (b-1) pushes past the next multiple → rounds up by 1

    Examples:
      ceil(7/3) = (7+2)/3 = 9/3  = 3 ✓
      ceil(6/3) = (6+2)/3 = 8/3  = 2 ✓
      ceil(1/4) = (1+3)/4 = 4/4  = 1 ✓

    Code: sum += (i + mid - 1) / mid;   // replaces ceil((double)i / mid)

    Advantage: avoids floating-point precision issues entirely.

[14] Popcount DP — Count Set Bits 0..n (LC 338)

    result[i] = result[i >> 1] + (i & 1);

    Idea: binary of i = binary of (i>>1) with one extra bit appended.
          So i has all the 1s of (i>>1), plus the dropped last bit.
      - i >> 1  : i with its lowest bit removed (already computed, < i)
      - i & 1   : the dropped bit — 1 if i is odd, else 0

    Example: i = 13 (1101) → i>>1 = 6 (110), result[6]=2; i&1=1 → result[13]=3 ✓

    Builds whole table in O(n) (each value reuses a smaller, ready one)
    vs O(n log n) counting bits per number from scratch.

    Code:
        vector<int> result(n + 1, 0);
        for (int i = 1; i <= n; ++i)
            result[i] = result[i >> 1] + (i & 1);

[15] Count Adjacent Set-Bit Pairs (LC 3950)

    pairs = popcount(n & (n >> 1));

    Idea: shifting n right by 1 lines up each bit with its left neighbour.
          A bit survives the AND only where BOTH n's bit i and bit i+1 are 1,
          i.e. exactly at each adjacent "11" pair. Popcount = number of pairs.

    Example: n = 6 (110)  → n>>1 = 011 → AND = 010 → popcount 1 → 1 pair
             n = 7 (111)  → n>>1 = 011 → AND = 011 → popcount 2 → 2 pairs
             n = 5 (101)  → n>>1 = 010 → AND = 000 → popcount 0 → 0 pairs

    Use case: "exactly one consecutive set bits pair" → check pairs == 1.

    Code: return __builtin_popcount(n & (n >> 1)) == 1;
